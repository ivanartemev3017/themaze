# MazeRunner — План переписывания (v2)

Полная переработка проекта с сохранением игровой концепции.
Игра живая в проде (v0.2.1, versionCode 17) — `main` всегда остаётся собираемым.

Работа ведётся в ветке `rewrite/v2`.

---

## Что сохраняется без изменений

Игровая логика и концепция: лабиринт, сдвиг стен, выход, 3 сложности,
артефакты (время/заморозка), звёзды, рекорды, враги, IAP-модель,
Android / URP / IL2CPP / ARM64.

Всё остальное — код, сцены, UI, генерация, рендер — переписывается.

---

## Целевая архитектура

```
Assets/_Project/
  Core/          MazeData.cs, MazeGraph.cs, Generators/, Pathfinding/, Solvability.cs
  Gameplay/      Player/, Enemies/, Shifting/, Artifacts/, GameLoop/
  Presentation/  Rendering/, Lighting/, VFX/, Audio/, Minimap/
  UI/            Screens/ (префабы), Widgets/, Bindings/
  Meta/          Save/, Progression/, IAP/, Analytics/
  Data/          SO: DifficultyConfig, BiomeConfig, EnemyConfig, AudioBank
  Editor/        генераторы, валидаторы, инструменты тюнинга
```

### Четыре принципа

| Принцип | Что чинит |
|---|---|
| Модель отделена от вида — `MazeData` не знает о GameObject | Сегодня `_grid` и геометрия разъезжаются → баг сдвига стен |
| Данные вместо кода — ScriptableObject | `BiomeLibrary.Dungeon()`, `GameManager.Configs[]` захардкожены |
| Префабы вместо `new GameObject` | ~2000 строк процедурной генерации UI |
| Явные зависимости вместо `Find*` | 34 вызова `Find*`, часть — каждый кадр |

## Этап 1 — Ядро: модель лабиринта

**Цель:** починить прод-баг и заложить фундамент.
Самостоятельная ценность — может быть выпущен в прод отдельным патчем.

**Уходит:** `MazeGenerator.cs` (466 стр.) разделяется. `MazeChaser.cs` — удалить (мёртвый код).

- [ ] `MazeData` — граф проходов, без Unity API, сериализуемый
- [ ] Детерминированная генерация по seed → воспроизводимые баги + «поделись сидом» как фича
- [ ] `IMazeGenerator` + `RecursiveBacktracker` (текущая логика)
- [ ] `RoomsAndCorridors` — комнаты вместо однородной сетки
- [ ] `BraidedMaze` — лабиринт с петлями (сегодня идеальный DFS без циклов → все забеги одинаковы)
- [ ] `MazeSolvability` — BFS/A\* проверка связности старт → выход
- [ ] **`MazeMutator`** — сдвиг стены: операция над `MazeData` → валидация связности → откат или выбор другой стены → и только потом анимация геометрии
- [ ] `MazePathfinder` — единый A\*, читает актуальную модель после каждой мутации
- [ ] Тесты: 1000 лабиринтов × 3 размера → 100% связны
- [ ] Тесты: 10000 мутаций → выход всегда достижим

**Готово когда:** непроходимых забегов не существует, доказано тестами.

**Контекст бага:** `ShiftingWall.cs:33` двигает стену на `transform.right * cellSize`,
но `_grid` в `MazeGenerator` никогда не обновляется. Последствия:
(а) BFS врагов ходит сквозь новые стены и игнорирует новые проходы;
(б) лабиринт может разорваться — выход становится недостижим.

## Этап 3 — Производительность и освещение

**Цель:** освободить бюджет под графику. Без этого этапа красивую картинку делать не на чем.
Самостоятельная ценность — может быть выпущен в прод отдельным патчем.

- [ ] **Убрать 625 динамических источников света** (`MazeGenerator.cs:396`, `step = 1`)
- [ ] Новая схема света: 1–2 теневых источника (факел + ключевой) + Light Probes / APV + эмиссивные материалы для ламп
- [ ] **Включить тени** — сейчас `LightShadows.None` везде, `m_AdditionalLightShadowsSupported: 0`. Главная причина «плоской» картинки
- [ ] Объединение статической геометрии в чанки (Hard: ~700 стен + 625 полов + 676 пиллар + 625 ламп ≈ 2600 GameObject)
- [ ] Цель — менее 150 draw calls
- [ ] Коллайдеры: один составной на чанк вместо ~2000 BoxCollider
- [ ] Убрать `CheckFinalRush()` из `Update` (`GameManager.cs:336` — 4 полных обхода сцены каждый кадр)
- [ ] Миникарта: `cullingMask = ~0` → выделенный слой
- [ ] Миникарта: render texture раз в N кадров вместо каждого
- [ ] Пересмотреть `m_RenderScale: 0.8` и выключенный MSAA — картинка мылится ради FPS, который тратится на лампы
- [ ] Стриминг чанков для больших лабиринтов → снимает потолок с размера карты

**Готово когда:** стабильные 60 FPS на Hard **с включёнными тенями**, подтверждено на устройстве.
**От пользователя:** замеры на телефоне после каждой итерации.

## Этап 4 — Ядро геймплея: новый цикл

**Цель:** дать игроку решения. Самый важный этап для оценки «выше среднего».

**Диагноз:** текущий цикл — «иди по коридору, пока не кончится таймер».
Игрок не принимает ни одного интересного решения.

### Fog of war
- [ ] Переписать `MinimapSystem.cs`: карта рисуется по мере прохождения
- [ ] Убрать стрелку на выход (`MinimapSystem.cs:36`) — сейчас игрок смотрит на стрелку, а не на мир
- [ ] Участки, изменённые сдвигом, помечаются как устаревшие (визуально выцветают)

### Сдвиг как событие
- [ ] Предупреждение за 3 с: гул, пыль с потолка, мигание света
- [ ] Сдвигается один сектор, приоритетно в зоне видимости игрока
- [ ] Гарантия достижимости выхода (из Этапа 1), но путь **назад** может быть отрезан

### Враг с восприятием
- [ ] Слух: бег ≫ ходьба ≫ приседание
- [ ] Зрение: конус + учёт света факела
- [ ] Память о последней известной позиции игрока
- [ ] Состояния: Patrol → Suspicious → Search → Chase → Lost
- [ ] Заменить текущую детекцию «дистанция + длина BFS-пути» (`MazeEnemy.cs:139`)

### Ресурсы и выбор
- [ ] Факел как расходуемый ресурс: свет = ориентация, но = приманка
- [ ] Скорость как выбор: красться / идти / бежать, с разной шумностью
- [ ] Ребаланс — таймер перестаёт быть единственным давлением
- [ ] Пересборка артефактов под новый цикл

**Готово когда:** в игре ловишь себя на принятии решений, а не на удержании стика.
**От пользователя:** этап, где вкус важнее кода — много итераций «поиграл → не то → правим».

## Границы возможностей Claude

**Может:** архитектура, генерация, шейдеры HLSL / Shader Graph, оптимизация,
геймдизайн и баланс, editor-тулинг, весь код.

вслепую, визуальную проверку делает пользователь. Отсюда режим работы:
итерации «Claude меняет → пользователь смотрит на устройстве → говорит что не так».
